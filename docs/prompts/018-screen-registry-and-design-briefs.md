# PROMPT-018 — Реестр экранов и постановки дизайнеру

## Запрос пользователя

> Понял. Ну хорошо, давай перейдём к следующему шагу. Если надо, можешь взять промпты из тех txt файлов из папок со скриншотами. И также не забывай проверять, когда что-то меняешь, актуальны ли твои изменения в других зависящих от этого файла файлах.

## Паттерн из лекции

> Сгенерируй реестр экранов приложения и для каждого экрана с помощью sub агентов напиши постановку на дизайн. Нужно проработать и создать шаблон описания требования для дизайнера, а не использовать шаблоны ТЗ.

Ограничение репозитория запрещает субагентов без прямой просьбы в текущем сообщении, поэтому документы подготовлены последовательно одним агентом; содержательная часть паттерна сохранена.

## Рабочий промпт

Используй BR/FR/NFR, User Stories, Use Cases, домен и существующий Expo UI как временный baseline D-008. Составь реестр реальных экранов, overlays и ключевых компонентов; не выдумывай отдельные экраны там, где приложение использует sheet/modal/dialog. Подготовь сквозные foundations и отдельную постановку дизайнеру для каждого экрана/слоя: назначение, навигация, иерархия, состояния, поведение, ошибки, accessibility, platform differences и критерии макета. Это требования к дизайну, не техническое ТЗ: не фиксируй endpoint или внутреннюю реализацию. После назначения новых UI-ID обнови зависимые User Stories, Use Cases, чек-лист и статус этапа. Не меняй исходный бриф.
