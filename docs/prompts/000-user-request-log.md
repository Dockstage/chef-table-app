# Исходные пользовательские запросы

Здесь сохранены пользовательские сообщения, которые определяли продукт, область работ и критерии готовности. Технические сообщения авторизации GitHub (`готово`, device login) не меняли артефакты продукта и в реестр не включены.

## Исходное задание

> В рамках одного из брифов повторить работы из лекций: сгенерировать требования к MVP (user stories и основные сценарии), получить архитектурный план и схему данных, реализовать минимум три функции, сгенерировать тест-кейсы и исправить от одного до трёх багов. Для каждой задачи и бага создать `.md`, описать цель или симптом, найти требования, приложить промпты, проверить вручную и сделать commit. Результат положить в GitHub.

## Выбор продукта

## Требование честного аудита

> Сравни ТЗ и то, что сделано на данный момент. Скажи, насколько всё соответствует ТЗ, только чистую правду.

## Требование устранить все расхождения

> Абсолютно всё из перечисленного надо обязательно исправить.

Структурированная выдержка из клиентского брифа сохранена в `docs/00-customer-brief.md`; исходный файл заказчика использован как первичный источник требований.
