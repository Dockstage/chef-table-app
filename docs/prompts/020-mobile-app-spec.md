# PROMPT-020 — Мобильное ТЗ

## Запрос пользователя

> Поехали.

Контекстом служил согласованный следующий шаг: после стабилизации дизайн-брифов, модели данных и OpenAPI подготовить полное мобильное ТЗ и проверить зависимые документы.

## Паттерн из лекции

> Используй требования для дизайна, готовый API и шаблоны ТЗ и с помощью sub агентов напиши все ТЗ на приложение.

Субагенты не использовались: текущие инструкции репозитория запрещают делегирование без прямой просьбы пользователя в этом сообщении. Все документы созданы последовательно по одному шаблону.

## Рабочий промпт

Используй канонические BR/FR/NFR, User Stories, Use Cases, дизайн-брифы, data model, API sequences и OpenAPI 1.1. Для каждого `SCR/BS/MDL/DLG` создай мобильное ТЗ: вход/выход, lifecycle, состояния Loading/Content/Empty/Error/Refreshing/Stale, элементы и источники данных, действия, навигация, валидация, operationId, обработка каждого применимого ответа и критерии приёмки. CMP опиши у экрана-владельца. Повторяемые правила вынеси в `LOGIC-*`: период/даты/фильтры, цена/прокат, идемпотентная запись, отмена, статусы/отзыв, push и сетевые состояния. Не выдавай текущее приложение за соответствующее целевому ТЗ; известные разрывы оставь в чек-листе разработки. После назначения ссылок обнови зависимые UC, реестр дизайн-брифов и чек-лист.
