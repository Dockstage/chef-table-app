# PROMPT-021 — Матрица трассировки

## Запрос пользователя

> Да, давай следующий шаг.

Контекстом служил согласованный следующий шаг: после завершения мобильного ТЗ создать сквозную матрицу трассировки и проверить зависимые документы.

## Рабочий промпт

Используй канонические BR/FR/NFR, User Stories, Use Cases, дизайн-брифы, мобильные ТЗ, OpenAPI, текущий код, тесты, TASK/BUG-карточки и Git-историю. Построй двунаправленно читаемую цепочку `BR → US/UC → FR/NFR → SCR/BS/LOGIC → API → код → TC → commit`. Для каждого требования честно укажи статус «полностью», «частично» или «не покрыто»: наличие спецификации не считать реализацией, unit-тест не считать native e2e, а отсутствие воспроизводимой проверки явно отметить. Добавь канонические FR/NFR в существующие тест-кейсы, сохранив legacy `R-*`. Обнови чек-лист и реестр промптов; исходный бриф не изменяй.
