# Чек-листы доработки проекта по материалам лекций

Дата аудита: 25.09.2026; актуализировано 28.09.2026 после завершения разработки. Сравнивались конспекты и 24 слайда разделов «Анализ», «Разработка», «Тестирование», структура примера `summer-school-2026-feature-client` и текущее состояние проекта.

Обозначения: **P0** — исправить до сдачи; **P1** — важно для соответствия лекциям; **P2** — полезное усиление. `[x]` означает, что артефакт уже существует и был проверен, `[ ]` — необходимая работа.

## Краткий вывод

Формальные условия задания выполнены: есть MVP, архитектура, восемь пользовательских возможностей, 25 тест-кейсов, 58 клиентских и 42 backend-теста, три исправленных бага, task/bug-документы, промпты и Git-история. Риски повторной брони при сетевом retry, смешения mutation/refresh и ошибочных UI-состояний устранены. На этапе тестирования ещё нужны раздельные layout/component/scenario-наборы и нативные проверки.

### Что переделать или добавить

- [x] **P0 — сделать retry бронирования идемпотентным.** Ключ создаётся на уровне пользовательской попытки, сохраняется после `NETWORK_ERROR`, повторно используется для того же payload и сбрасывается после однозначного результата либо изменения данных формы.
- [x] **P0 — обновлять данные после конфликта бронирования.** После `SLOT_FULL`, `SLOT_CANCELLED` и `RENTAL_UNAVAILABLE` клиент отдельно получает актуальный класс; состояние формы привязано к ID и не сбрасывается при замене данных класса.
- [x] **P0 — отделить успешную бронь от сбоя refresh.** Серверный результат сразу добавляется в «Мои записи», форма закрывается, а ошибка последующего обновления сообщает об устаревших данных и не предлагает повторить создание.
- [x] **P0 — отделить остальные мутации от сбоя refresh.** Результаты отмены и отзыва применяются локально до фонового обновления; повторная отмена подтягивает актуальную бронь, а сбой refresh не маскирует успех.
- [x] **P0 — реализовать настоящий Error State.** Расписание и записи имеют независимые `initial/loading/content/empty/error/refreshing/stale`; первичная ошибка постоянна и содержит «Повторить», refresh сохраняет старые данные, а недоступная архивная карточка получает fallback.
- [x] **P0 — проверить push payload по контракту.** Runtime parser проверяет точный `type`, UUID `bookingId`, непустой `reason` до 500 символов и отсутствие лишних полей. Foreground сохраняет вкладку; tap/cold start открывает историю и адресно перечитывает серверную бронь.
- [x] **P1 — декомпозировать `client/App.tsx`.** Файл стал компактным composition root и только создаёт API/собирает приложение; theme/layout/primitives, feature screens/overlays, `application/StudioApp` и `application/useStudioApp` разделяют UI, shell и orchestration.
