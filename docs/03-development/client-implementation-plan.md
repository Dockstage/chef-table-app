# План реализации клиента

## Цель и исходное состояние

Сохранить работающий Expo/React Native/TypeScript-клиент и привести его к отдельной модульной части monorepo. Уже реализованы восемь пользовательских возможностей, `MockStudioApi`, `HttpStudioApi`, push-модуль и Vitest-тесты. Главные пробелы перечислены в [`lecture-gap-checklists.md`](../lecture-gap-checklists.md): монолитный `App.tsx`, нестабильный retry, смешение mutation/refresh, неполные error states и недостаточная проверка входящих данных.

## Целевая структура

```text
client/
  App.tsx
  src/
    app/
    domain/
    data/
    features/
      schedule/
      booking/
      bookings/
      review/
      profile/
    notifications/
    shared/ui/
    shared/theme/
  tests/
```

`App.tsx` остаётся composition root. UI, application state, API adapters и чистые бизнес-правила не смешиваются в одном файле.

## Итерационный чеклист

### CL-00 — Перенос в monorepo без изменения поведения

- [x] Один раз зафиксировать исходный результат `typecheck`, тестов и web export.
- [x] Перенести Expo-файлы, `src/`, `tests/` и Node manifests в `client/`.
- [x] Проверить `.gitignore`, обновить README, пути команд и ссылки; общие `docs/` оставить в корне.
- [x] Повторить те же проверки из `client/` и подтвердить отсутствие функциональных изменений.

Результат: до и после переноса TypeScript прошёл без ошибок, Vitest выполнил 24/24 теста, Expo создал web bundle. Существующие рекурсивные правила `.gitignore` подходят для `client/node_modules`, `.expo`, `.npm-cache`, `dist` и `.env`, поэтому менять их не потребовалось.

### CL-01 — Инструменты качества

- [x] Добавить ESLint и Prettier с командами `lint` и `format:check`.
- [x] Проверить Expo-совместимость зависимостей и задокументировать результат `npm audit` без `--force`.
- [x] Добавить client-проверки в CI после стабилизации структуры.

Результат TASK-051: зависимости приведены к ожидаемым Expo patch-версиям. `npm audit` и `npm audit --omit=dev` сохраняют 10 moderate по одной транзитивной цепочке `expo → @expo/config-plugins → xcode → uuid@7.0.3`. Уязвимый сценарий относится к передаче buffer в UUID v3/v5/v6 внутри native project tooling; приложение эти API не вызывает. npm предлагает только несовместимый откат до Expo 46 через `--force`, поэтому риск временно принят до исправления upstream.

Результат TASK-052: workflow `Client CI` на push/PR воспроизводит `npm ci`, lint, format check, typecheck, 55 тестов и web-export. Права ограничены чтением, повторные запуски одной ветки отменяются. Все пункты CL-01 закрыты.

## Зависимости между планами

`CL-00` выполняется до активной backend-разработки. `CL-01`–`CL-04` можно выполнять параллельно логически, но последовательно в Git. `CL-05`–`CL-07` сверяются с соответствующими `BE-05`–`BE-07`. `CL-09` начинается только после миграций, seed и нужных endpoint backend.

## Правило итерации

Каждый `CL-*` получает TASK/PROMPT, минимальное изменение, релевантные тесты и focused commit. Полный suite не запускается повторно, если после его результата не менялись влияющие файлы.
