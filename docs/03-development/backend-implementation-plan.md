# План реализации backend

## Цель и границы

Создать отдельный FastAPI backend для клиентского MVP «Шеф-стол» по принятому [ADR-001](../01-analysis/decisions/ADR-001-own-backend.md). Канонический контракт — [`docs/02-design/openapi.yaml`](../02-design/openapi.yaml), модель хранения — [`data-model.md`](../02-design/data-model.md). В скоуп входят расписание, карточка класса, бронирования, отмена, отзыв и регистрация push-токена. Админка, production OTP, оплата, APNs/FCM-провайдер и deployment не входят в MVP.

## Стек и архитектурные правила

- Python 3.12+, FastAPI, Uvicorn, Pydantic Settings.
- SQLAlchemy 2, Alembic, PostgreSQL; PostgreSQL-драйвер выбирается и фиксируется в `pyproject.toml`.
- pytest, httpx, Ruff; проверка типов добавляется только после выбора совместимого инструмента.
- Слои: `api` → `services` → `domain`/`repositories`; `db` реализует repository contracts.
- HTTP handlers валидируют транспорт и вызывают services, но не управляют бизнес-транзакциями.
- Все даты — ISO 8601 с offset, правила считаются в `Europe/Moscow`.
- Секреты и персональные данные не попадают в Git и логи.

## Доменные сущности

`Client`, `Chef`, `Program`, `CookingClass`, `Booking`, `Review`, `PushToken`, `IdempotencyRecord`. Статусы, nullability, связи, ограничения и владение определены в `docs/02-design/data-model.md`.

## Итерационный чеклист

### BE-00 — Каркас и инструменты

- [x] Создать `backend/pyproject.toml`, зафиксировать версии Python и зависимостей.
- [x] Создать `app/api`, `domain`, `services`, `repositories`, `schemas`, `db` и `main.py`.
- [x] Добавить команды запуска, format, lint и test; реализовать `GET /health`.

Готово, когда чистое окружение устанавливается, FastAPI стартует, Ruff и pytest проходят.

Результат: зависимости установлены в чистое `.venv` под Python 3.12.10; Ruff format/lint и pytest проходят, Uvicorn запускается, `GET /health` возвращает `200` и `{"status":"ok"}`.

### BE-01 — PostgreSQL, Docker, миграции и seed

- [x] Добавить корневой `compose.yaml`, `backend/Dockerfile`, `.env.example` и healthchecks.
- [x] Создать Alembic-миграцию всех сущностей, FK, unique/check constraints и индексов.
- [x] Добавить отдельный идемпотентный seed с demo-клиентом и всеми UI-состояниями.
- [x] До реализации endpoint поднять контейнеры, применить миграции и seed, как требует лекционный порядок.

Готово, когда upgrade работает на пустой БД, повторный seed безопасен, а последняя миграция проходит downgrade/upgrade.

Результат: Docker Compose поднимает healthy PostgreSQL 16 и FastAPI; миграция создаёт восемь доменных таблиц, FK, индексы и ограничения. Проверены `downgrade → upgrade`, отсутствие autogenerate diff, повторный seed с неизменными количествами (9 классов, 5 броней) и отклонение отрицательного остатка/дубликата активной брони.

### BE-02 — Общая HTTP-инфраструктура и dev-auth

- [ ] Добавить settings, CORS, request ID и безопасное логирование.

Готово, когда `401`, validation errors и неизвестные ресурсы возвращаются в контрактном формате.

Готово, когда все семь `operationId` имеют реализацию либо явно отмеченный ожидаемый пробел.

## Правило итерации

Каждый `BE-*` выполняется отдельной небольшой итерацией: TASK и PROMPT → код/миграция → тесты → одна документированная проверка → focused commit. Чекбокс закрывается только после выполнения критерия готовности.
