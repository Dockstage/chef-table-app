# Бриф заказчика: кулинарная студия «Шеф-стол»

Источник: файл `brief-cooking (1).md`, предоставленный заказчиком учебного проекта. Полный текст сохранён в [`docs/source/brief-cooking.md`](source/brief-cooking.md).

Студия проводит групповые кулинарные классы продолжительностью около трёх часов. Клиенту требуется мобильное приложение для просмотра расписания, записи на класс, выбора аренды рабочего набора, отмены записи и оценки шефа.

## Подтверждённые ограничения

- Текущая поставка предназначена только для роли «Клиент».
- Админка, интерфейс шефа и формирование расписания уже существуют и не входят в проект.
- Существующий backend — источник истины. Он атомарно проверяет наличие мест.
- Клиент работает через документированный API-контракт и обрабатывает конфликт бронирования.
- По умолчанию показываются классы на ближайшие 7 дней; более длинный период доступен через фильтр дат.
- API передаёт тариф и свободный прокатный фонд рабочих наборов.
- При отмене студией бронь сохраняется со статусом «Отменён студией» и причиной.
- При отмене студией клиент получает push-уведомление.
- Повторная запись на отменённый класс запрещена.
- Исторических данных и миграции legacy-схемы нет.

## Учебное расширение поставки

Исходный заказ предполагает интеграцию с существующим backend. Для повторения полного цикла из лекций учебная поставка дополнительно включает собственную референсную реализацию backend на FastAPI и PostgreSQL. Это проектное решение не изменяет исходный бриф; его основания, границы и последствия зафиксированы в [`ADR-001`](01-analysis/decisions/ADR-001-own-backend.md).
