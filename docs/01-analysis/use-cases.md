# Основные сценарии

## UC-01: Записаться на класс

**Предусловия:** клиент авторизован, слот активен, есть свободное место.

1. Клиент открывает расписание.
2. Выбирает дату и уровень.
3. Открывает карточку класса.
4. Нажимает «Записаться».
5. Выбирает свой набор или аренду.
6. Указывает аллергии либо подтверждает их отсутствие.
7. Проверяет итог и подтверждает запись.
8. API возвращает подтверждённую бронь.
9. Приложение открывает «Мои классы» и показывает бронь.

Альтернативы:

- место заняли параллельно — `409 SLOT_FULL`, данные расписания обновляются;
- активная бронь уже существует — `409 DUPLICATE_BOOKING`;
- класс отменён — `410 SLOT_CANCELLED`;
- пропала сеть — введённые данные сохраняются в форме до повтора.

## UC-02: Отменить бронь

1. Клиент открывает активную бронь.
2. Приложение проверяет дедлайн.
3. Клиент подтверждает отмену.
4. API меняет статус на `cancelled_by_client`.
5. Бронь остаётся в истории, место возвращается в остаток.

Если до класса меньше 12 часов, действие блокируется и показывается причина.

## UC-03: Оценить шефа

1. Клиент открывает завершённую посещённую бронь.
2. Выбирает 1–5 звёзд и при желании оставляет комментарий.
3. API сохраняет отзыв.
4. Повторная отправка для той же брони запрещена.

## UC-04: Получить отмену студией

1. Клиент включает уведомления в профиле.
2. Приложение получает системное разрешение и нативный токен.
3. API связывает токен с текущим клиентом.
4. После отмены backend отправляет `class_cancelled`.
5. Приложение обрабатывает событие в foreground, при нажатии по уведомлению или при холодном запуске.
6. Приложение обновляет брони и открывает «Мои классы».
7. Во вкладке «История» видны статус «Отменён студией» и причина.
