# Use Cases

## UC-01 — Записаться на класс

| Поле | Значение |
|---|---|
| Цель | Получить подтверждённую бронь одного места без превышения остатков |
| Основной актор | Авторизованный клиент |
| Заинтересованные стороны | Клиент — получить достоверное подтверждение; студия — получить данные записи без двойной брони |
| Триггер | Клиент нажимает «Записаться» в доступном классе |
| Предусловия | Demo-клиент идентифицирован; карточка класса загружена; API доступен для отправки команды |
| Успешное постусловие | Создана одна `confirmed`-бронь; место и при необходимости прокат уменьшены один раз; бронь видна в «Предстоящих» |
| Минимальная гарантия | При отказе новая бронь и списание остатков не подтверждаются; введённые данные сохраняются для безопасного повтора |
| Связи | US-03; BR-001, BR-002; FR-005–FR-008, FR-015; NFR-004, NFR-006–NFR-008, NFR-011 |
| Интерфейс | SCR-001 → CMP-001 → BS-001 → SCR-002 |

### Основной поток

1. Клиент открывает расписание, выбирает класс и переходит к деталям.
2. Приложение показывает актуальные цену, места, прокатный тариф и остаток наборов.
3. Клиент нажимает «Записаться».
4. Выбирает свой или прокатный набор и при необходимости вводит аллергии.
5. Приложение валидирует выбор и длину текста, рассчитывает итог в копейках и показывает подтверждение.
6. После подтверждения приложение создаёт `Idempotency-Key` для логической попытки и отправляет команду с Bearer-токеном.
7. Backend в транзакции проверяет клиента, статус класса, повторную активную бронь, место и прокат.
8. Backend создаёт бронь, уменьшает применимые остатки и возвращает `201`.
9. Приложение очищает форму, обновляет данные и показывает бронь в «Моих записях».

### Альтернативы и исключения

- **A1 — ошибка формы:** вариант инвентаря не выбран или аллергии длиннее 300 символов — отправка не выполняется, поле получает подсказку.
- **A2 — нет авторизации:** отсутствующий/невалидный токен — `401`, бронь не создаётся, показывается ошибка доступа.
- **A3 — место заняли:** `409 SLOT_FULL` — форма сохраняется, слот обновляется, клиент видит, что место недоступно.
- **A4 — закончился прокат:** `409 RENTAL_UNAVAILABLE` — форма сохраняется, остаток обновляется, клиент может выбрать свой набор.
- **A5 — повторная запись:** `409 DUPLICATE_BOOKING` — вторая бронь не создаётся, приложение предлагает открыть существующую.
- **A6 — класс отменён:** `410 SLOT_CANCELLED` — слот обновляется, запись запрещена, показывается причина отмены.
- **A7 — потерян ответ/timeout:** повтор выполняется с теми же ключом и payload; backend возвращает исходный результат без второй брони.
- **A8 — payload изменён после timeout:** начинается новая логическая попытка с новым ключом; старый ключ нельзя переиспользовать для другого payload.
- **A9 — offline/5xx:** ложный успех не показывается; форма остаётся заполненной, доступен повтор после восстановления связи.

## UC-02 — Отменить бронь

| Поле | Значение |
|---|---|
| Цель | Отменить собственную запись в допустимый срок и освободить ресурсы |
| Основной актор | Авторизованный клиент |
| Заинтересованные стороны | Клиент — понимать результат; студия — вернуть место и прокат без повторного увеличения |
| Триггер | Клиент выбирает отмену в предстоящей брони |
| Предусловия | Бронь принадлежит клиенту и имеет статус `confirmed` |
| Успешное постусловие | Статус `cancelled_by_client`; бронь в истории; место и прокат возвращены ровно один раз |
| Минимальная гарантия | При отказе серверное состояние не меняется, подтверждённая бронь остаётся видимой |
| Связи | US-04; BR-003; FR-009–FR-011, FR-015; NFR-005, NFR-007 |
| Интерфейс | SCR-002 / CMP-002 → DLG-001 → SCR-002 |

### Основной поток

1. Клиент открывает «Мои записи» и выбирает `confirmed`-бронь.
2. Приложение показывает время класса, дедлайн и действие отмены.
3. Клиент нажимает «Отменить» и подтверждает решение.
4. Backend проверяет владельца, актуальный статус и условие `now <= startsAt - 12h` в `Europe/Moscow`.
5. В транзакции backend меняет статус и возвращает место и прокат.
6. Приложение обновляет списки и показывает бронь в истории.

### Альтернативы и исключения

- **A1 — ровно 12 часов:** отмена разрешена по основному потоку.
- **A2 — дедлайн прошёл:** backend возвращает `409 CANCELLATION_CLOSED`; состояние не меняется, UI объясняет ограничение.
- **A3 — студия уже отменила класс:** приложение обновляет данные и показывает `cancelled_by_studio` с причиной без повторного возврата ресурсов.
- **A4 — повтор команды:** backend не возвращает ресурсы второй раз; клиент перечитывает актуальное состояние.
- **A5 — offline/timeout/5xx:** локально бронь не помечается отменённой; ранее подтверждённые данные остаются видимыми, доступен повтор.

## UC-03 — Оценить шефа

| Поле | Значение |
|---|---|
| Цель | Сохранить обратную связь после посещённого класса |
| Основной актор | Авторизованный клиент |
| Заинтересованные стороны | Клиент — оставить отзыв; студия — получить однозначную оценку конкретного посещения |
| Триггер | Клиент выбирает «Оценить» в посещённой брони |
| Предусловия | Бронь принадлежит клиенту, имеет статус `attended`, отзыв отсутствует |
| Успешное постусловие | Сохранён один отзыв с целой оценкой 1–5 и необязательным комментарием до 500 символов |
| Минимальная гарантия | При ошибке существующий отзыв не меняется; несохранённый ввод остаётся в форме |
| Связи | US-05; BR-005; FR-009, FR-012, FR-015; NFR-005 |
| Интерфейс | SCR-002 / CMP-002 → MDL-001 → SCR-002 |

### Основной поток

1. Клиент открывает историю и выбирает `attended`-бронь без отзыва.
2. Приложение показывает имя шефа, выбор 1–5 и необязательный комментарий.
3. Клиент выбирает оценку, при желании вводит комментарий и отправляет форму.
4. Backend проверяет владельца, статус, диапазон, длину и отсутствие прежнего отзыва.
5. Backend сохраняет отзыв и возвращает его представление.
6. Приложение показывает сохранённую оценку и убирает повторное действие.

### Альтернативы и исключения

- **A1 — невалидная форма:** нет оценки, значение не целое/не 1–5 или комментарий длиннее 500 — запрос не отправляется.
- **A2 — статус не `attended`:** действие отсутствует; прямой запрос отклоняется с `REVIEW_NOT_ALLOWED`.
- **A3 — отзыв уже существует:** `409 REVIEW_NOT_ALLOWED`; исходный отзыв остаётся без изменений.
- **A4 — offline/timeout/5xx:** введённые оценка и комментарий сохраняются до повтора, успех не показывается.

## UC-04 — Получить уведомление об отмене студией

| Поле | Значение |
|---|---|
| Цель | Узнать об отмене и увидеть актуальную причину в истории |
| Основной актор | Авторизованный клиент с бронью |
| Вторичные акторы | ОС устройства, push-провайдер, внешняя система студии |
| Триггер | Клиент включает уведомления; позднее студия отменяет его класс |
| Предусловия | Android/iOS; приложение установлено; для доставки пользователь дал разрешение и токен зарегистрирован |
| Успешное постусловие | После события брони обновлены; отменённая запись находится в истории со статусом и причиной |
| Минимальная гарантия | Отказ/ошибка push не блокирует приложение; актуальное состояние доступно после ручного обновления |
| Связи | US-06; BR-003, BR-004; FR-011, FR-013, FR-014; NFR-005, NFR-009 |
| Интерфейс | SCR-003 → системное разрешение; событие → SCR-002 / CMP-002 |

### Основной поток

1. Клиент в профиле явно включает уведомления.
2. Приложение запрашивает системное разрешение.
3. После согласия приложение получает нативный токен и регистрирует его для текущего клиента.
4. Внешняя система студии отменяет класс и сохраняет причину; связанные брони становятся `cancelled_by_studio`.
5. Backend формирует событие `class_cancelled` для зарегистрированных устройств.
6. Устройство получает push, приложение обрабатывает его и перечитывает брони.
7. При открытии уведомления приложение показывает «Мои записи» → «История» со статусом и причиной.

### Альтернативы и исключения

- **A1 — разрешение отклонено:** токен не регистрируется; профиль объясняет ограничение, остальные сценарии доступны.
- **A2 — web-preview:** системный запрос не выполняется; показано, что push поддерживается только на Android/iOS.
- **A3 — регистрация токена не удалась:** настройка не показывается как успешно подключённая; доступен повтор.
- **A4 — foreground:** данные обновляются без обязательной навигации, пользователь видит актуальный статус.
- **A5 — нажатие/cold start:** после инициализации открывается история; обработанный response очищается, чтобы не повторять переход.
- **A6 — дубликат события:** повторная обработка только перечитывает состояние и не создаёт новых доменных данных.
- **A7 — offline/5xx при обновлении:** ранее загруженные записи сохраняются, показана ошибка и доступен ручной повтор.
