# Нефункциональные требования

НФТ применяются к клиенту и референсному backend в пределах учебного MVP. Для каждого требования задано воспроизводимое условие проверки; production SLA намеренно не придумывается.

| ID | Требование | Условие проверки | Приоритет | Источник |
|---|---|---|---|---|
| NFR-001 | Основной экран интерактивен не позднее 2 секунд | Release-сборка, Android-устройство/эмулятор с 4 CPU и 4 GB RAM, стабильная сеть не менее 10 Мбит/с и ответ API не более 500 мс; не менее 19 из 20 запусков укладываются в 2 с от появления React Native root до доступности фильтров | Should | Исходное НФТ; OQ-008 ограничивает перенос результата на production |
| NFR-002 | Интерфейс не ломается на поддерживаемой ширине | При viewport 360×800 px расписание, карточка, формы и нижняя навигация читаемы, основные действия доступны, горизонтального переполнения страницы нет | Must | R-012; TC-023 |
| NFR-003 | Основные сценарии доступны для касания и чтения | Интерактивная область каждого основного действия не меньше 44×44 dp; контраст обычного текста не ниже 4.5:1, крупного — 3:1, проверка выполняется инспектором/контраст-анализатором | Must | Исходное НФТ; WCAG AA как принятый baseline |
| NFR-004 | Конкурентные запросы не нарушают целостность | Для одного оставшегося места из 20 одновременных запросов создаётся не более одной новой брони; остальные получают контрактный отказ; повтор одного идемпотентного запроса не меняет остатки | Must | BR-002; BRULE-006–BRULE-009 |
| NFR-005 | Временная ошибка чтения не уничтожает подтверждённые данные в UI | После timeout/5xx ранее загруженные подтверждённые брони остаются видимыми, показывается состояние ошибки и доступен повтор | Must | Исходное НФТ; BR-003 |
| NFR-006 | Чувствительные данные не попадают в технические каналы | Автотест с перехватом application/access/error logs подтверждает отсутствие текста аллергий и Bearer-токенов; клиентские ошибки не выводят эти значения | Must | Q-008; BRULE-005; OQ-002 |
| NFR-007 | Деньги и время передаются без неоднозначности | Все денежные значения API — целые копейки; даты — ISO 8601 с offset; дедлайн рассчитывается в `Europe/Moscow`; форматирование выполняется только для отображения | Must | Q-009; Q-016; BRULE-004; BRULE-014; D-007 |
| NFR-008 | Контракт API проверяется автоматически | `docs` OpenAPI остаётся источником истины; схема FastAPI проходит compatibility/schema check в CI, а несовместимое изменение завершает проверку ошибкой | Must | D-005; ADR-001 |
| NFR-009 | Целевые платформы определены явно | Функциональные сценарии проверяются на Android и iOS; web используется только как demo-preview, а отсутствие web-push объясняется пользователю | Must | Q-014; Q-015 |
| NFR-010 | Must-требования допускают сквозную проверку | Перед сдачей каждый Must ID связан хотя бы с одним тест-кейсом, а каждый тест-кейс — с требованием; автоматические и ручные проверки различены | Must | Условие задания; метрика BR |
| NFR-011 | Учебная авторизация имеет минимально безопасную границу | Защищённые endpoint без валидного Bearer-токена отвечают `401`; токены/секреты поступают из окружения и отсутствуют в отслеживаемых Git-файлах | Must | Q-002; D-004; ADR-001 |
| NFR-012 | Основной путь записи остаётся коротким | От появления загруженных деталей BS-001 до отправки валидной брони требуется не более пяти управляющих действий; tap, выбор и подтверждение считаются отдельно, а ввод любого объёма текста в одно поле — одним действием | Should | Метрика BR-001; US-03; TC-025 |

## Ограничения интерпретации

- Профиль производительности фиксирует учебную проверку, а не production SLA.
- Реальные push-ключи, production-auth, нагрузка, retention и мониторинг остаются в `OQ-001`, `OQ-004`, `OQ-006`–`OQ-009`.
- Значение НФТ меняется только через журнал решений с обновлением затронутых тестов.
