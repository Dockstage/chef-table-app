# User Stories

Истории оформлены в формате **Card / Conversation / Confirmation**. Приоритет — MoSCoW; ссылки ведут на канонические требования и подробный Use Case.

## US-01 — Просмотреть расписание

**Card:** Как клиент, я хочу видеть и фильтровать доступные классы, чтобы выбрать удобные дату и уровень.

**Метаданные:** Must · источник: бриф, Q-003 · требования: BR-001, BR-006, FR-001, FR-002, FR-004, FR-015, NFR-001–NFR-003, NFR-009, NFR-011 · интерфейс: SCR-001, CMP-001.

**Conversation:** По умолчанию показываются 7 дней, доступны периоды 14/30 дней. Уровень не сбрасывает дату. Завершённые и отменённые классы не предлагаются для записи. Нужны явные loading/content/empty/error states.

**Confirmation:**

| Сценарий | Given | When | Then |
|---|---|---|---|
| Период по умолчанию | Расписание доступно | Клиент впервые открывает «Классы» | Выбраны 7 дней и показаны классы диапазона |
| Расширение периода | Выбраны дата и уровень | Клиент выбирает 14 или 30 дней | Диапазон расширяется, дата и уровень сохраняются |
| Фильтрация | В выбранной дате есть разные уровни | Клиент меняет уровень | Остаются подходящие классы, дата не меняется |
| Нет результата | Для комбинации нет классов | Запрос завершён | Показано «Пока нет доступных классов», а не ошибка |
| Ошибка | API недоступен | Запрос завершается ошибкой | Показаны понятная причина и повтор запроса |

## US-02 — Изучить класс

**Card:** Как клиент, я хочу изучить программу и условия класса, чтобы принять решение о записи.

**Метаданные:** Must · источник: бриф, Q-007, Q-009 · требования: BR-001, BR-006, FR-003, FR-006, FR-015, NFR-002, NFR-003, NFR-007, NFR-011 · интерфейс: CMP-001, BS-001.

**Conversation:** Детали включают меню, шефа, уровень, адрес, начало, длительность, основную цену, доплату за прокат и остатки. Последнее место выделяется, недоступный класс нельзя подтвердить.

**Confirmation:**

| Сценарий | Given | When | Then |
|---|---|---|---|
| Полные детали | Класс существует | Клиент открывает карточку | Все обязательные поля совпадают с ответом API |
| Цена проката | У класса есть тариф проката | Карточка открыта | Основная цена и доплата показаны отдельно в рублях |
| Последнее место | `availableSeats = 1` | Карточка открыта | Видно предупреждение о последнем месте |
| Недоступный класс | Класс завершён или отменён | Клиент открывает детали | Причина видна, действие записи отсутствует или недоступно |

## US-03 — Забронировать место

**Card:** Как клиент, я хочу забронировать одно место и сообщить об аллергиях, чтобы студия подготовилась к моему визиту.

**Метаданные:** Must · источник: бриф, Q-004–Q-009 · требования: BR-001, BR-002, BR-006, FR-005–FR-008, FR-015, NFR-004, NFR-006–NFR-008, NFR-011, NFR-012 · сценарий: UC-01 · интерфейс: BS-001, SCR-002.

**Conversation:** Клиент выбирает свой или прокатный набор; аллергии необязательны и ограничены 300 Unicode code points. Одна логическая попытка использует стабильный `Idempotency-Key`. Только backend подтверждает остатки и уникальность.

**Confirmation:**

| Сценарий | Given | When | Then |
|---|---|---|---|
| Успешная запись | Класс активен, место и выбранный прокат доступны | Клиент подтверждает валидную форму | Создана одна бронь, показана в «Предстоящих», остатки уменьшены один раз |
| Повтор запроса | Первый ответ потерян | Клиент повторяет тот же payload с тем же ключом | Возвращена исходная бронь без повторного списания остатков |
| Место занято | Последнее место заняли конкурентно | Клиент подтверждает | Получен `409 SLOT_FULL`, ложного успеха нет, слот обновляется |
| Прокат закончился | `rentalAvailable = 0` | Клиент выбирает прокат или отправляет устаревшую форму | Выбор заблокирован либо получен `409 RENTAL_UNAVAILABLE` |
| Повторная бронь | У клиента уже есть активная бронь | Клиент подтверждает | Получен `409 DUPLICATE_BOOKING`, вторая бронь не создана |
| Класс отменён | Студия отменила класс | Клиент подтверждает устаревшую форму | Получен `410 SLOT_CANCELLED`, введённые данные не превращаются в бронь |

## US-04 — Управлять своей записью

**Card:** Как клиент, я хочу видеть свои записи и заранее отменять бронь, чтобы освободить место и сохранить понятную историю.

**Метаданные:** Must · источник: бриф, Q-010, Q-011 · требования: BR-003, BR-006, FR-009–FR-011, FR-015, NFR-005, NFR-007, NFR-011 · сценарий: UC-02 · интерфейс: SCR-002, CMP-002, DLG-001.

**Conversation:** Предстоящие и история разделены. Ровно за 12 часов отмена разрешена, позже — запрещена. Клиентская отмена возвращает место и прокат один раз; отмена студией сохраняет причину.

**Confirmation:**

| Сценарий | Given | When | Then |
|---|---|---|---|
| Граница дедлайна | До начала ровно 12 часов | Клиент подтверждает отмену | Бронь отменена, ресурсы возвращены, запись перенесена в историю |
| Поздняя отмена | До начала меньше 12 часов | Клиент открывает бронь | Отмена недоступна или отклонена с объяснением |
| Отмена студией | Класс отменён внешней системой | Клиент обновляет записи | В истории видны `cancelled_by_studio` и причина |
| Ошибка обновления | Ранее загруженные брони видны | API отвечает timeout/5xx | Данные не исчезают, показаны ошибка и повтор |

## US-05 — Оценить шефа

**Card:** Как посетивший класс клиент, я хочу оценить шефа, чтобы помочь студии улучшать качество.

**Метаданные:** Should · источник: бриф, Q-013 · требования: BR-005, BR-006, FR-009, FR-012, FR-015, NFR-005, NFR-011 · сценарий: UC-03 · интерфейс: SCR-002, CMP-002, MDL-001.

**Conversation:** Отзыв доступен только для `attended`, один раз на бронь. Оценка — целое 1–5, комментарий необязателен и не длиннее 500 Unicode code points.

**Confirmation:**

| Сценарий | Given | When | Then |
|---|---|---|---|
| Успешный отзыв | Бронь `attended` ещё не оценена | Клиент отправляет 1–5 и валидный комментарий | Отзыв сохранён и показан в истории |
| Неверные данные | Форма открыта | Оценка отсутствует/вне диапазона или текст длиннее 500 | Отправка заблокирована с подсказкой |
| Повтор | Отзыв уже существует | Клиент повторяет отправку | Получен `REVIEW_NOT_ALLOWED`, первый отзыв не изменён |
| Неподходящий статус | Бронь не `attended` | Клиент открывает запись | Действие оценки отсутствует |

## US-06 — Получить отмену студией

**Card:** Как записанный клиент, я хочу узнать об отмене класса, чтобы своевременно изменить планы.

**Метаданные:** Must · источник: бриф, Q-011, Q-014, Q-015 · требования: BR-004, BR-006, FR-011, FR-013–FR-015, NFR-005, NFR-009, NFR-011 · сценарий: UC-04 · интерфейс: SCR-003, SCR-002, CMP-002.

**Conversation:** Разрешение запрашивается только из профиля после действия пользователя. В MVP поддерживается только `class_cancelled`. Android/iOS получают нативный push; web показывает ограничение. Любой путь открытия обновляет брони.

**Confirmation:**

| Сценарий | Given | When | Then |
|---|---|---|---|
| Подключение | Нативное приложение, разрешение ещё не запрошено | Клиент включает уведомления | Запрошено системное разрешение, токен зарегистрирован после согласия |
| Отказ | Клиент отклоняет системное разрешение | Приложение получает отказ | Основные сценарии работают, профиль объясняет, как включить уведомления |
| Foreground | Приложение открыто | Приходит `class_cancelled` | Брони обновлены, отмена и причина видны в истории |
| Нажатие/cold start | Приложение свёрнуто или закрыто | Клиент открывает уведомление | Открыты «Мои записи», данные обновлены, response очищен |
| Web | Запущен web-preview | Клиент открывает настройки уведомлений | Показано, что push доступен только в Android/iOS |
