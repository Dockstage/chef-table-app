# Требования на дизайн · SCR-002 · Мои записи

**Тип:** верхнеуровневый экран · **Приоритет:** Critical · **Статус:** актуально для MVP · **Baseline:** `BookingsScreen`.

**Источники:** [Foundations](00-foundations.md), US-04–US-06, FR-009–FR-014, NFR-005, NFR-007.

## Назначение

Показывать клиенту постоянный результат бронирования, разделять предстоящие записи и историю, давать допустимую отмену и отзыв после посещения.

## Навигация

- Вход: таб «Мои записи», успешная запись из BS-001, открытие push `class_cancelled`.
- «Отменить запись» открывает [DLG-001](DLG-001-cancel-confirm.md).
- «Оценить шефа» открывает [MDL-001](MDL-001-chef-review.md).
- Табы «Предстоящие» / «История» не меняют основной bottom navigation tab.

## Иерархия

1. Хедер «Мои классы».
2. Сегмент «Предстоящие / История».
3. Список CMP-002 либо Loading/Empty/Error.
4. Нижняя навигация.

## CMP-002 — Карточка брони

Обязательные элементы: текстовый статус, итоговая цена, дата, название, время и шеф. Состояния карточки:

| Статус | Раздел | Дополнительное содержание/действие |
|---|---|---|
| `confirmed` | Предстоящие | Обратный отсчёт; отмена либо disabled «Отмена закрыта» |
| `attended` | История | «Оценить шефа», если отзыва нет; иначе сохранённые оценка и комментарий |
| `cancelled_by_client` | История | «Вы отменили», без primary-действия |
| `cancelled_by_studio` | История | «Отменён студией» и заметный блок причины |

Статус различается текстом и оформлением, не только цветом. Причина студийной отмены не обрезается до потери смысла.

## Состояния и поведение

| Состояние | Требование к дизайну |
|---|---|
| Loading | Скелетоны карточек; прежние данные не исчезают при refresh |
| Content | Карточки соответствуют выбранному сегменту и актуальному серверному статусу |
| Empty upcoming | «Здесь пока пусто» + действие/подсказка перейти к расписанию |
| Empty history | Нейтральное сообщение без предложения отменять/оценивать несуществующую запись |
| Error первичный | Сообщение + «Повторить» |
| Refresh error | Старые подтверждённые данные остаются; виден retry |
| Cancelling/reviewing | Busy только на затронутом действии; повторное нажатие заблокировано |

## Критерии для макета

- Пользователь за один взгляд отличает предстоящую запись от завершённой и отменённой.
- Дедлайн объяснён рядом с disabled-действием, а не только через отсутствие кнопки.
- После push история и причина доступны без поиска по расписанию.
- Предусмотрены длинные название класса, имя шефа, причина и комментарий.
