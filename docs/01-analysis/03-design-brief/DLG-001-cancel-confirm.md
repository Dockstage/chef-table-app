# Требования на дизайн · DLG-001 · Подтверждение отмены

**Тип:** системный dialog · **Приоритет:** High · **Статус:** актуально для MVP · **Baseline:** `Alert.alert` / browser `confirm`.

**Источники:** [Foundations](00-foundations.md), US-04, UC-02, FR-010, NFR-005, NFR-007.

## Назначение

Предотвратить случайную отмену и честно объяснить последствие перед необратимым изменением статуса.

## Содержание

- Заголовок: «Отменить запись?».
- Текст: «Место станет доступно другим гостям.».
- Безопасное действие: «Оставить» — закрывает dialog без запроса.
- Destructive-действие: «Отменить запись» — запускает команду отмены.

На iOS/Android используется системный dialog с нативным порядком действий. В web-preview допустим browser confirm с тем же вопросом и смыслом.

## Предусловия и поведение

- Dialog открывается только для `confirmed` при допустимом дедлайне. Ровно за 12 часов отмена ещё разрешена.
- После destructive tap повторное действие блокируется до ответа; сама карточка показывает процесс.
- Успех: dialog закрыт, карточка перемещена в историю как `cancelled_by_client`, ресурсы возвращены сервером.
- `CANCELLATION_CLOSED`: бронь остаётся подтверждённой, действие становится «Отмена закрыта», показывается объяснение.
- Если студия уже отменила класс, показывается актуальный `cancelled_by_studio` с причиной, без второго возврата ресурсов.
- Offline/timeout/5xx: dialog закрывается либо показывает системный результат по платформе, но карточка не меняет статус локально; доступен повтор.

## Критерии для макета

- Destructive и безопасное действие нельзя перепутать; default focus не должен провоцировать отмену.
- Текст не обещает возврат денег: онлайн-оплаты в MVP нет.
- Machine code и HTTP-статус пользователю не показываются.
