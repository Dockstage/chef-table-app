# Требования на дизайн · Foundations

**Статус:** актуально для MVP · **Версия:** 1.0 · **Основание:** D-008, NFR-002, NFR-003, NFR-005–NFR-009.

Документ описывает сквозные правила. Экранные брифы не должны копировать их целиком.

## 1. Продукт и контекст

«Шеф-стол» — мобильное приложение самостоятельной записи в кулинарную студию. Клиент обычно выбирает класс заранее с телефона; важны быстрое сравнение дат, доверие к наличию места и ясное объяснение цены/отмены. Интерфейс должен быть тёплым и гостеприимным, но не скрывать ограничения за декоративностью.

## 2. Принципы

| ID | Принцип | Следствие для макета |
|---|---|---|
| DP-001 | Сначала решение клиента | Дата, время, меню, цена и остаток заметнее декоративного контента |
| DP-002 | Один понятный следующий шаг | На каждом слое один primary CTA; вторичные действия визуально тише |
| DP-003 | Серверу можно доверять | Loading/submitting видимы; конфликт не маскируется успехом; введённые данные по возможности сохраняются |
| DP-004 | Статус читается без цвета | Текст и форма/иконка дублируют цвет каждого статуса |
| DP-005 | Чувствительные сведения защищены | Аллергии не повторяются вне формы и не показываются в toast/error |
| DP-006 | Только клиентский scope | В навигации нет действий шефа, владельца и управления расписанием |

## 3. Визуальный baseline

Текущая палитра служит временным baseline, а не утверждённым брендом:

| Роль | Значение | Применение |
|---|---|---|
| Canvas | `#F5F0E8` | фон приложения |
| Surface | `#FFFDF8` | карточки и sheet |
| Text | `#21211F` | основной текст |
| Muted | `#77736B` | пояснения |
| Border | `#E3DDD2` | разделители |
| Primary | `#C64F33` | главный CTA/акцент |
| Success | `#355C50` / `#E0EBE5` | подтверждение |
| Warning | `#985C20` / `#FAECD8` | ограничение |
| Danger surface | `#F8DFD8` | отмена/причина |

- Используется системный шрифт; уровни: экранный заголовок, заголовок карточки, основной текст, caption.
- Конкретное значение можно изменить только системно, сохранив контраст NFR-003 и смысловые роли.
- Цена, время и остаток должны иметь более высокий визуальный вес, чем вторичные подписи.

## 4. Сетка, навигация и слои

- Mobile-first, одна колонка, минимальная поддерживаемая область 360×800 px без горизонтального overflow.
- Основные боковые поля — 20–22 px baseline; дизайнер может нормализовать их общей шкалой.
- Нижняя навигация содержит только «Классы», «Мои записи», «Профиль» и видна на SCR-001–SCR-003.
- BS-001 открывается поверх таба снизу; MDL-001 — центрированный modal; DLG-001 использует системный dialog.
- Back/close не должен отправлять данные или показывать ложный успех.
- Клавиатура не перекрывает активное поле и primary CTA.

## 5. Состояния

| Состояние | Обязательное представление |
|---|---|
| Loading | Скелетон предпочтителен; допустим индикатор, если не имитируется пустой контент |
| Content | Актуальные данные и доступные действия |
| Empty | Причина отсутствия данных и полезный следующий шаг |
| Error первичной загрузки | Сообщение без технических деталей и кнопка «Повторить» |
| Refresh error | Сохранён прежний подтверждённый контент, ненавязчивое сообщение и повтор |
| Submitting | Индикатор на CTA, форма заблокирована от повторной отправки |
| Conflict | Предметная причина, обновление серверных данных, сохранение безопасного ввода |

## 6. Компоненты и доступность

- Интерактивная зона — не меньше 44×44 dp; иконка закрытия также соответствует минимуму.
- Контраст: 4.5:1 для обычного текста, 3:1 для крупного; disabled остаётся читаемым.
- Кнопки, сегменты, radio и звёзды имеют role, label и selected/disabled state для screen reader.
- Горизонтальная лента дат прокручивается, но выбранная дата всегда различима без одной лишь смены цвета.
- Dynamic Type/увеличенный текст не скрывает CTA: контент скроллится, строки не обрезают критичные значения.
- Toast не является единственным носителем критического результата; новая бронь/статус видны в постоянном контенте.

## 7. Tone of voice

- Обращение на «вы», короткие спокойные фразы, без обвинения пользователя.
- Ошибка отвечает на три вопроса: что произошло, изменились ли данные, что делать дальше.
- Не показывать stack trace, HTTP-термины и machine code; они остаются в диагностике/контракте.
- Канонические тексты: «Пока нет доступных классов», «Оплата в студии», «Отмена закрыта», «Отменён студией».

## 8. Platform differences

- Android/iOS: нативные safe areas, системное push-разрешение и системный dialog отмены.
- Web-preview: адаптивная телефонная рамка допустима; push обозначен как недоступный; подтверждение отмены может использовать browser confirm с тем же смыслом.
- Макет не должен обещать web-push или production-auth.
