# Требования к MVP

Канонические требования разделены по уровню:

- [`business-requirements.md`](business-requirements.md) — бизнес-цели `BR-*`;
- [`functional-requirements.md`](functional-requirements.md) — наблюдаемое поведение `FR-*`;
- [`non-functional-requirements.md`](non-functional-requirements.md) — измеримые ограничения качества `NFR-*`.

Старые `R-*` сохраняются только как legacy-ID для существующих TASK/BUG и тест-кейсов. Пропуски `R-014`, `R-016`–`R-026` возникли исторически при последовательных уточнениях и не означают отсутствующие требования. Новые документы используют независимые непрерывные пространства ID.

## Соответствие legacy-ID

| Legacy ID | Историческая формулировка | Канонические ID |
|---|---|---|
| R-001 | Клиент видит классы на ближайшие 7 дней | FR-001 |
| R-002 | Клиент фильтрует расписание по дате и уровню | FR-002 |
| R-003 | Карточка показывает программу, шефа, время, цену и свободные места | FR-003 |
| R-004 | Backend атомарно подтверждает место; клиент обрабатывает конфликт | FR-007, FR-008, NFR-004 |
| R-005 | Клиент бронирует одно место и выбирает свой или прокатный набор | FR-005, FR-006 |
| R-006 | Перед бронированием клиент сообщает об аллергиях | FR-005, NFR-006 |
| R-007 | Клиент видит активные и прошлые брони | FR-009 |
| R-008 | Отмена студией сохраняется в истории с причиной | FR-011, FR-014 |
| R-009 | Клиент отменяет бронь не позднее чем за 12 часов | FR-010 |
| R-010 | После посещённого класса клиент ставит шефу оценку 1–5 один раз | FR-012 |
| R-011 | Клиент видит понятные loading, empty и error states | FR-004 |
| R-012 | Интерфейс адаптирован под экран от 360 px | NFR-002, NFR-003 |
| R-013 | После отмены класса студией клиент получает push и приложение обновляет бронь с причиной | FR-013, FR-014 |
| R-015 | API передаёт свободный прокатный фонд; недоступный прокат нельзя выбрать или подтвердить | FR-006, FR-008 |
| R-027 | По умолчанию показаны 7 дней; клиент может расширить период до 14 или 30 дней | FR-001 |
| R-028 | В текущей поставке доступна только роль клиента; управление расписанием и интерфейсы шефа/владельца не реализуются | FR-016 |

## Вне MVP

- админка и интерфейс шефа;
- создание и редактирование расписания;
- production-auth, онлайн-оплата и программа лояльности;
- чат со студией и управление закупками;
- production push-инфраструктура, SLA и аналитика.

При противоречии канонические `BR-*`, `FR-*`, `NFR-*`, журнал решений и ADR имеют приоритет над legacy-формулировками.
