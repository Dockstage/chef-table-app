# Требования к MVP

## Цель

Снизить ручную нагрузку владельца студии и исключить ситуации, когда клиент приезжает на уже заполненный класс.

## Функциональные требования

| ID | Требование | Приоритет |
|---|---|---|
| R-001 | Клиент видит классы на ближайшие 7 дней | Must |
| R-002 | Клиент фильтрует расписание по дате и уровню | Must |
| R-003 | Карточка показывает программу, шефа, время, цену и свободные места | Must |
| R-004 | Backend атомарно подтверждает место; клиент обрабатывает `409` | Must |
| R-005 | Клиент бронирует одно место и выбирает свой или прокатный набор | Must |
| R-006 | Перед бронированием клиент сообщает об аллергиях | Must |
| R-007 | Клиент видит активные и прошлые брони | Must |
| R-008 | Отмена студией сохраняется в истории с причиной | Must |
| R-009 | Клиент отменяет бронь не позднее чем за 12 часов | Must |
| R-010 | После посещённого класса клиент ставит шефу оценку 1–5 один раз | Should |
| R-011 | Клиент видит понятные loading, empty и error states | Must |
| R-012 | Интерфейс адаптирован под экран от 360 px | Must |
| R-015 | API передаёт свободный прокатный фонд; недоступный прокат нельзя выбрать или подтвердить | Must |
| R-027 | По умолчанию показаны 7 дней; клиент может расширить период до 14 или 30 дней | Must |

## Нефункциональные требования

- Основной экран становится интерактивным не позднее 2 секунд на среднем телефоне при нормальной сети.
- Все интерактивные элементы имеют область нажатия не меньше 44×44 px.
- Ошибка API не уничтожает локально отображаемые подтверждённые брони.
- Цена рассчитывается в целых копейках, форматируется только на UI.
- В API не логируются сведения об аллергиях.
- Контраст текста соответствует WCAG AA там, где это применимо.

## Вне MVP

- админка и интерфейс шефа;
- создание и редактирование расписания;
- онлайн-оплата;
- программа лояльности;
- чат со студией;
- реальный сервис push-уведомлений;
- управление закупками продуктов.

## Метрики успеха

- 100% подтверждённых броней проходят серверную проверку наличия места;
- 0 повторных активных броней одного клиента на один класс;
- основной сценарий записи выполняется не более чем за 5 действий после выбора класса;
- все Must-требования покрыты хотя бы одним тест-кейсом.
