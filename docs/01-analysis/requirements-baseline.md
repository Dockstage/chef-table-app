## Gate передачи в разработку

- вопросы, блокирующие учебный MVP, закрыты; production-вопросы явно отложены;
- BR/FR/NFR, US/UC имеют стабильные ID, приоритет и источник;
- критерии проверяемы, основные и альтернативные сценарии описаны;
- UI-ID, модель данных, API и мобильное ТЗ связаны с требованиями;
- противоречия и влияние изменений проверены матрицей и QA-ревью;
- открытые расхождения реализации находятся в `lecture-gap-checklists.md` и не меняют статус baseline.

Отдельная подпись заказчика не требуется по D-011. Изменение scope или поведения после этой точки выполняется только по правилам ниже.

## Версионирование и изменения

Формат версии: `MAJOR.MINOR`.

- `MAJOR` — несовместимое изменение бизнес-цели, scope, статуса/семантики API или основного пользовательского сценария.
- `MINOR` — совместимое добавление или уточнение требования, сценария, интерфейсного артефакта либо проверяемого ограничения.
- Редакционная правка без изменения смысла версию не повышает, но остаётся видна в Git.

Для содержательного изменения обязательно:

1. создать TASK/BUG и сохранить PROMPT;
2. указать источник решения в decision log либо ADR;
3. выполнить impact analysis по стабильным ID;
4. обновить затронутые дизайн/API/ТЗ/TC;
5. изменить версию baseline и добавить строку в историю;
6. зафиксировать результат отдельным commit.

ID удалённого требования не переиспользуется. Заменённое решение сохраняется в журнале со статусом `Заменено`.
