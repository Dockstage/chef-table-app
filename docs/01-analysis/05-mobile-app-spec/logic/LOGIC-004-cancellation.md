# LOGIC-004 · Дедлайн и отмена брони

**Приоритет:** High · **Точки:** CMP-002, DLG-001 · **Требования:** FR-009–FR-011, NFR-007 · **Use Case:** UC-02.

## Доступность действия

Клиентский preview:

```text
canCancel = booking.status == confirmed
         && now <= class.startsAt - 12 hours
```

Сравниваются абсолютные timestamps; отображение дедлайна — в `Europe/Moscow`. Ровно за 12 часов действие доступно. Backend всегда повторяет проверку и является источником решения.

## Поток

1. Для доступной отмены tap открывает DLG-001.
2. «Оставить» закрывает dialog без запроса.
3. «Отменить запись» один раз вызывает `cancelBooking`, блокирует повторный tap.
4. `200` возвращает `cancelled_by_client`; карточка сразу переносится в историю, затем запускается независимый refresh.
5. Если refresh не удался, mutation response остаётся видимым, а UI показывает устаревание/повтор.

## Ошибки

- `404 BOOKING_NOT_FOUND` — убрать недостоверную локальную запись только после успешного перечитывания; предложить refresh.
- `409 CANCELLATION_CLOSED` — оставить `confirmed`, заменить действие на «Отмена закрыта», обновить данные.
- `409 BOOKING_NOT_ACTIVE` — перечитать брони; показать актуальный статус/причину.
- Timeout/5xx — не менять статус оптимистически; дать повтор.

Возврат места и проката выполняет backend ровно один раз; клиент не изменяет остатки арифметически.

## Критерии

- Граница `12:00:00` разрешена, `11:59:59.999` — закрыта.
- Повтор команды не увеличивает остатки второй раз.
- Отмена студией никогда не отображается как отмена клиентом.
