# LOGIC-005 · Группировка броней и доступность отзыва

**Приоритет:** High · **Точки:** SCR-002, CMP-002, MDL-001 · **Требования:** FR-009, FR-011, FR-012.

## Группировка

| Статус | Раздел | Действия |
|---|---|---|
| `confirmed` | Предстоящие | Отмена по LOGIC-004 |
| `attended` | История | Оценка, только если `rating == null` |
| `cancelled_by_client` | История | Нет mutation-действий |
| `cancelled_by_studio` | История | Нет mutation-действий; показать `studioCancellationReason` |

Внутри раздела сортировать по `startsAt`: предстоящие — ближайшие сначала; историю — последние события/классы сначала. Если класс отсутствует в текущем расписании, получить его через `getClass(classId)`; отсутствие класса не должно молча скрывать Booking.

## Отзыв

- MDL-001 доступен только для `attended` и `rating == null`.
- `rating` — обязательное целое 1–5; `comment` необязателен, до 500 символов.
- `201` возвращает обновлённый Booking: закрыть modal и показать `rating`/`reviewComment` в CMP-002.
- `409 REVIEW_NOT_ALLOWED` — закрыть повторное действие после refresh; существующий отзыв не перезаписывать.
- Timeout/5xx — сохранить ввод modal и не показывать сохранённую оценку.

## Nullability

По контракту `studioCancellationReason`, `rating`, `reviewComment` присутствуют всегда и могут быть `null`. UI не различает missing/null: missing считается нарушением контракта и логируется, а не превращается в выдуманное значение.

## Критерии

- Ни один статус не попадает одновременно в оба раздела.
- `cancelled_by_studio` всегда показывает непустую причину.
- Оценённая бронь не показывает CTA повторного отзыва.
