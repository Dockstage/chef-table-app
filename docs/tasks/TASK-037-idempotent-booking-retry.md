# TASK-037 — Идемпотентный retry бронирования

## Цель

Выполнить первую часть CL-05: исключить создание новой брони при повторе после неопределённого сетевого результата.

## Требования

`FR-007`, `UC-01`, `LOGIC-003`, клиентский план CL-05 и P0 из чеклиста лекций.

## Промпт

[`docs/prompts/037-idempotent-booking-retry.md`](../prompts/037-idempotent-booking-retry.md).

## Выполнено

- генерация ключа перенесена из HTTP-адаптера на уровень пользовательской попытки;
- один ключ сохраняется для неизменённого payload после `NETWORK_ERROR`;
- изменение payload, успех или предметная ошибка завершают попытку;
- `StudioApi` требует явный ключ, а HTTP-адаптер передаёт его без замены;
- добавлены unit- и HTTP-тесты стабильного retry.
