# BUG-001 — Повторная активная бронь

## Симптом

Mock API создаёт вторую активную бронь того же класса для текущего клиента.

## Требования

R-004, US-03: активная бронь уникальна по клиенту и классу; ожидается `409 DUPLICATE_BOOKING`.

## Шаги воспроизведения

1. Инициализировать API с активной бронью класса.
2. Вызвать `createBooking` для того же `classId`.
3. Проверить список броней.

Факт: вторая бронь создаётся. Ожидание: предметная ошибка `DUPLICATE_BOOKING`.

## Промпт

> Проверь MockStudioApi на нарушение инварианта уникальной активной брони `(userId, classId)`. Добавь сначала воспроизводящий тест, затем минимальную сервероподобную проверку до изменения остатка. Не считай клиентский UI достаточной защитой.

## Исправление и проверка

До уменьшения остатка добавлена проверка существующей брони со статусом `confirmed`. Регрессионный тест сначала воспроизвёл создание второй брони, после исправления получил `DUPLICATE_BOOKING`. Полный прогон: 11/11 тестов успешно.
