# «Шеф-стол» — мобильное приложение кулинарной студии

Учебный MVP клиентского приложения для просмотра расписания и самостоятельной записи на кулинарные классы. Проект проходит полный цикл задания: анализ требований, архитектура и API, четыре реализованные функции, тест-кейсы, найденные баги, исправления и Git-история.

## Что реализовано

- расписание на ближайшие 7 дней и фильтр по уровню;
- карточка класса с меню, шефом, ценой и остатком мест;
- запись с выбором своего/прокатного набора и сведениями об аллергиях;
- раздел предстоящих и прошлых записей;
- отмена записи с дедлайном 12 часов;
- сохранение отмены студией вместе с причиной;
- оценка шефа после посещённого класса;
- loading, empty, success и предметные error states;
- доступные подписи и состояния интерактивных элементов.

Приложение использует асинхронный `MockStudioApi`. Он имитирует существующий backend и соблюдает тот же контракт, включая серверные конфликты `SLOT_FULL`, `SLOT_CANCELLED` и `DUPLICATE_BOOKING`.

## Технологии

- Expo SDK 57;
- React Native 0.86 и React 19;
- TypeScript в strict-режиме;
- Vitest;
- OpenAPI 3.1;
- Mermaid для архитектурных схем.

Один проект запускается на Android, iOS и в браузере. Для проверки задания достаточно web-preview; production-сборки Android/iOS создаются стандартными средствами Expo/EAS.

## Быстрый запуск

Требования: Node.js 22.13 или новее и npm.

```bash
npm install
npm run web
```

После запуска открыть адрес, который покажет Expo, обычно `http://localhost:8081`.

Запуск на телефоне через Expo Go:

```bash
npm start
```

Затем отсканировать QR-код из терминала. Для нативной production-сборки потребуется настроенный Expo/EAS аккаунт.

## Проверки

```bash
npm run typecheck
npm test
npm run export:web
```

Ожидаемый результат:

- TypeScript — без ошибок;
- 11 автоматических тестов — успешно;
- web bundle — создаётся в `dist/`.

## Демонстрационные сценарии

1. На главном экране выбрать день и уровень класса.
2. Открыть карточку, выбрать прокатный набор и указать аллергию.
3. Подтвердить запись — приложение откроет «Мои записи».
4. В предстоящих классах проверить отмену студией и её причину.
5. В истории открыть завершённую «Домашнюю пасту» и поставить шефу оценку.

Даты тестовых классов вычисляются относительно текущего дня, поэтому демо не протухает.

## Границы MVP

В репозитории реализована только роль клиента. Админка, интерфейс шефа, формирование расписания, реальная база, онлайн-оплата, лояльность и доставка push-уведомлений находятся вне скоупа. В production `MockStudioApi` заменяется HTTP-адаптером к существующей инфраструктуре.

## Структура

```text
App.tsx                  интерфейс и application state
src/domain/              типы и чистые бизнес-правила
src/data/                demo-данные и MockStudioApi
tests/                   автоматические тесты
docs/                    аналитика, проектирование и отчёты
```
